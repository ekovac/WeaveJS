# CLAUDE.md

WeaveJS is the HTML5 front end of Weave, last actively developed in 2016 and revived in 2026 so it builds again. The Flash client and Java services live in the `Weave` git submodule (its own repo; see `Weave/CLAUDE.md`).

## Build

```
./scripts/bootstrap.sh       # once; installs the toolchain into .toolchain/ and runs npm install
. .toolchain/env.sh          # every shell (fish: source .toolchain/env.fish)
npm run compile-libs         # third-party bundle: dist/libs.js
npm run compile              # WeaveASJS -> JS, then TypeScript: dist/weavejs.js, dist/core/
npm run compile-weave        # Flash client + WeaveServices.war in the submodule (ant dist)
./build-release-package.sh   # all of the above, packaged as weave-release-<date>.zip
```

Always build with the `.toolchain` environment loaded; the system Java/Node will not work.

- **Java 7 only.** Flex 4.5.1's compiler and the FlexJS 0.6.0 compiler need it. Under Java 8, Weave fails with "Parameter initializer unknown or is not a compile-time constant".
- **Node 6 / npm 3.** The build uses TypeScript 1.8, Babel 6 and browserify 12.
- **npm dependencies are pinned to exact versions** as of 2016-09-02, the last upstream commit. Caret ranges pulled in releases that need React 15+ while React is 0.14.7, and `libs.js` then threw at load time. Don't loosen or upgrade a pin without checking the result in a browser.
- `WeaveASJS/build.js` runs the FlexJS compiler from `$FLEXJS_HOME`. The `flexjs` npm package was dropped: its installer is interactive and most of its download URLs are dead.
- `scripts/bootstrap.sh` pins every download by SHA-256. If a URL dies or a hash changes, update both the URL and the hash together.
- `npm run compile-weave` restores the two `weave_version.txt` files the Weave build stamps, so the submodule stays clean.

## Layout

- `WeaveASJS/src/`: ActionScript core (sessioning, data, geometry), compiled to JS by FlexJS. `.actionScriptProperties` is read by the compiler (`-fb`), not just by the IDE.
- `srcts/weavejs/`: TypeScript/React UI. `srcts/_references.ts` and `srcts/_lib-references.ts` are generated by `scripts/main-import-tool.ts`; don't edit them.
- `typings/`: committed third-party `.d.ts` files (provenance in `tsd.json`). `typings/weave/weavejs-core.d.ts` is generated from WeaveASJS.
- `scripts/`: build helpers run through `run-ts.js`.
- `src/`: static HTML, CSS and images copied into `dist/` by `scripts/copy.ts`.

## Testing

There is no automated test suite. To smoke-test, serve `dist/` with any static server and load `/` (splash screen) and `/weave.html?file=test-nba.weave` (any `weave_sessions/*.weave` file works) in a browser, watching the console. Data sources that call `/WeaveServices/...` need `Weave/WeaveServices.war` deployed in a servlet container. Without it they show empty.

Known noise: about 15 `<rect> attribute height: Expected length, "NaN"` errors on `test-nba.weave`, and React 0.14 `isMounted` deprecation warnings.

## Decisions already made

- WeaveJS will not be published as an npm library. The module packaging was removed on purpose; don't reintroduce it.
- The FlasCC/CrossBridge C code in the Weave submodule is not rebuilt; its committed `weave_flascc.swc` is used as-is. WeaveJS doesn't use FlasCC at all.
- Weave's default branch is `develop`; WeaveJS's is `main`.
